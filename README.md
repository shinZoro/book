# Her 21st Birthday Book

A digital flip-through book: a closed cover, 21 two-page spreads (a quote image
on the left, a handwritten note image on the right), and a closing scene with
an epilogue and a "did you like it?" reveal. Everything is edited from a
password-protected admin panel — no code changes needed to add content.

## Running it

```bash
npm install
cp .env.example .env   # then edit ADMIN_PASSWORD in .env
npm start
```

- Book (what she sees): http://localhost:3000/
- Admin panel (where you upload things): http://localhost:3000/admin.html

The admin password defaults to `letmein` if you don't set `ADMIN_PASSWORD` —
change it in `.env` before sending the link to anyone.

## How it's put together

- `server.js` — small Express server. Serves the site, stores uploaded images
  in `public/uploads/`, and stores all text/layout data in `data/content.json`
  (auto-created on first run). Reading the content is public (that's how the
  book renders for her); writing it requires the admin login.
- `public/index.html` + `public/js/book.js` + `public/css/style.css` — the
  book itself: cover opening animation, page-turn transitions between
  spreads, and the closing/reveal scene.
- `public/admin.html` + `public/js/admin.js` + `public/css/admin.css` — the
  editor: upload the cover, epilogue, and true-cover images; for each of the
  21 pages, upload a quote image (drag to reposition, drag the corner handle
  to resize) and a note image (fills the page, margin adjustable); set the
  global page margin and the two closing messages.

## Editing content

1. Go to `/admin.html` and log in.
2. **Front Cover** — upload the closed-book cover image.
3. **Page 1–21** — for each page: upload a quote image on the left (drag/resize
   it however looks right), upload a handwritten note image on the right, and
   optionally override that page's margin.
4. **Epilogue** — the image shown when the book closes again at the end.
5. **True Cover** — the image revealed full-screen if she says she liked the
   book, plus the messages for "Yes" and "Not really".
6. **Global Settings** — the default margin (in px) used on every note page
   unless a page overrides it.
7. Click **Save** in the top bar after each set of changes.

Anything left empty just shows a soft placeholder in the book, so you can fill
it in over time without breaking anything.

## Deploying

This needs a Node process running (not a static host like GitHub Pages),
since the admin panel writes uploads and content to disk. Below is the free
path using [Render](https://render.com) — any small Node host works the same
way (Railway, Fly.io, a VPS, etc.), just via that host's own dashboard.

### The catch with free hosting, and how this repo works around it

Free tiers on hosts like Render sleep after inactivity and wipe their disk on
every sleep/restart/redeploy. Normally that would mean losing every image
you'd uploaded through the admin panel. So unlike a typical app, **this repo
intentionally does not gitignore `data/content.json` or `public/uploads/`** —
they're meant to be committed. That way a redeploy just re-checks-out the
same files from git instead of starting from empty. The workflow:

1. Run the app locally (see "Running it" above) and use `/admin.html` to set
   up pages as usual.
2. Whenever you're happy with how things look, commit and push:
   ```bash
   git add data/content.json public/uploads
   git commit -m "Update book content"
   git push
   ```
3. If auto-deploy is on (the default), Render redeploys automatically and the
   live site now shows exactly what you just committed.

**Always edit locally, then commit/push** — don't rely on editing through the
admin panel on the *live* Render site, since anything saved there only lives
on that instance's disk and can vanish on the next sleep/restart. Treat the
deployed site as the "published" version and your local machine as the
editor.

### One-time setup on Render

1. Push this repo to GitHub (already done if you're reading this from there).
2. Go to [render.com](https://render.com), sign up/log in, click **New +** →
   **Web Service**, and connect this GitHub repo. Render will detect
   `render.yaml` in the repo and pre-fill the build/start commands and plan
   (free tier) for you — just confirm.
3. When prompted for environment variables, set `ADMIN_PASSWORD` to whatever
   you want (`SESSION_SECRET` is auto-generated by the blueprint). You can
   change `ADMIN_PASSWORD` later from the service's **Environment** tab.
4. Click **Create Web Service**. First deploy takes a couple of minutes.
5. You'll get a URL like `https://birthday-book-xxxx.onrender.com` — that's
   the link you send her. `/admin.html` on that same URL is the live admin
   panel (for occasional live tweaks — but see above, prefer editing locally).

Free-tier caveat: after ~15 minutes with no visitors, the service sleeps: the
next visit takes 30-60 seconds to wake up, then loads normally. If that's not
acceptable for the actual birthday moment, open the link yourself a minute or
two beforehand to wake it up, or upgrade the Render service to a paid "always
on" plan later.
